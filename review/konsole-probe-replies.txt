SOURCE AUDIT (why the matrix was misleading)
--------------------------------------------
processGraphicsToken() handles a=t/T/q; a=r is not in that set and is
ignored entirely (no reply, no render). The ENOTSUPPORTED branch fires on
`q < 2 && t != 'd'` — i.e. it is t=f that gets rejected, not f=24. The
rendering path (addPlacement, source=Kitty) is reached for:
  - a=T with m=0  -> decoded, stored, DRAWN
  - a=p           -> paste of a stored image, drawn
a=t stores only (never drawn).

Rendering semantics (Screen::addPlacement + TerminalPainter):
  - anchored at the cursor cell when the APC arrives (row=_cuY, col=_cuX);
    drawn at native pixel size at (col*fontWidth + X, row*fontHeight + Y)
    -> pixel-exact when the image size is a multiple of the cell size
  - kitty placements (z>=0) are painted ABOVE the text (overlay; the text
    under the image is kept)
  - C=1 -> the cursor is not moved; C=0 (default) -> moved past the image
  - same id+pid is replaced in place (send p=0 explicitly: pid=-1, the
    default, is only garbage-collected when fully covered)
  - delete: a=d with d=i (by image id) / d=a (all) / d=z / d=x / d=y
  - A= alpha, X/Y pixel offsets, z z-index, q=0 -> i=N;OK reply

So Konsole DOES support the kitty graphics protocol; the diagnostic form is
a=T t=d (a=r is invisible to it, t=f is rejected).

PROBE CONSEQUENCE (implemented in src/ui/term_probe.cpp)
--------------------------------------------------------
Test transfer: i=99,p=0,f=24,s=1,v=1,a=T,t=d,q=0,C=1;AAAA
  - Konsole / compliant terminal: renders the pixel, replies i=99;OK
  - handler that cannot render a=T: replies an error -> kitty off
The reply window is 400 ms (a 150 ms window once raced a slow reply),
plus a matching drain so late replies cannot leak into the UI input.
